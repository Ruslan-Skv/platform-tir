# Удалённая помощь (Remote Help)

Функционал админки, позволяющий суперадмину подключиться к экрану сотрудника
(менеджера, замерщика и т.д.), чтобы помочь ему в работе с приложением:
видеть его экран и удалённо нажимать/вводить текст **внутри окна приложения**.

## Как это работает

- **Транспорт**: WebRTC P2P — сотрудник захватывает экран через
  `navigator.mediaDevices.getDisplayMedia()` и шлёт видеопоток суперадмину.
  Сигналинг (offer/answer/ICE) идёт через socket.io-шлюз `/remote-help`
  (`backend/src/admin/remote-help/remote-help.gateway.ts`), события `help:signal`.
- **Управление**: суперадмин водит мышью и печатает прямо по видео на странице
  `/admin/remote-help`; события мыши/колеса/клавиатуры нормализуются
  (учитывается `object-fit: contain`) и уходят по WebRTC DataChannel `control`.
  На стороне сотрудника они воспроизводятся в его странице: клики через
  `document.elementFromPoint` + dispatch событий, текст — через native setter
  (чтобы React ловил onChange) и `execCommand('insertText')` для
  contenteditable (TipTap). Плюс красный указатель «куда нажать».
- **Согласие**: сессия начинается только после явного «Разрешить» сотрудника
  (клик по кнопке — обязательный user gesture для выбора экрана). Сотрудник в
  любой момент завершает сеанс кнопкой в баннере или через «Stop sharing»
  браузера; таймаут неотвеченного приглашения — 90 секунд.
- **Аудит**: все сеансы пишутся в таблицу `remote_help_sessions`
  (кто, кому, статусы, время начала/конца, причина завершения).

## Сценарии

1. **Приглашение суперадмином**: `/admin/remote-help` → «Онлайн-сотрудники» →
   «Подключиться» → у сотрудника во всех вкладках админки всплывает модалка →
   «Разрешить» → выбор экрана (рекомендуется делиться вкладкой/окном приложения) →
   видео у суперадмина → тумблер «Управление».
2. **Запрос сотрудником**: плавающая кнопка «🎧 Запросить помощь» внизу справа →
   тост всем суперадминам → «Принять» на странице удалённой помощи → далее как в п.1.

## Роли и доступ

- Раздел `admin.remote-help` в сайдбаре виден только SUPER_ADMIN (ресурс не входит
  в `ROLE_DEFAULT_RESOURCES`; суперадмин обходит проверку).
- REST-эндпоинты `/api/v1/admin/remote-help/*` исключены из
  `AdminResourceInterceptor` (см. `ADMIN_API_SKIPPED_PREFIXES`): роли и владение
  сессией проверяет сам контроллер — приглашения/claim/cancel/история только
  SUPER_ADMIN, requests/accept/decline/end — сотрудник-владелец сессии.
- Шлюз `/remote-help` авторизует JWT в handshake (как мессенджер), SUPER_ADMIN
  дополнительно входит в комнату `helpers`.

## Ограничения (осознанные)

- Управление работает **только внутри окна приложения в браузере** — браузер не
  позволяет синтетическими событиями управлять всей ОС. Нативные файловые
  диалоги и системные хоткеи недоступны; для полного контроля рабочего стола
  нужен отдельный инструмент (RustDesk/RDP).
- Координаты кликов точны, когда сотрудник делится вкладкой/окном приложения
  (трансляция всего экрана может вносить смещение из-за рамок окна).
- WebRTC за симметричным NAT требует TURN-сервер (см. ниже). Без TURN работает
  через публичный STUN — достаточно, когда обе стороны в одной сети.

## TURN (опционально)

1. Раскомментируйте сервис `coturn` в `docker-compose.infra.yml` и задайте
   `TURN_USERNAME`/`TURN_CREDENTIAL`.
2. В `.env` бэкенда укажите `TURN_URL=turn:<host>:3478` и те же креды.
3. Клиенты получают ICE-конфиг с `GET /api/v1/admin/remote-help/ice-servers`
   (STUN Google зашит по умолчанию).
