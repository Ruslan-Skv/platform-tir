# Тестирование процесса оформления заказов

В проекте реализовано тестирование сценариев оформления заказов из каталога товаров и каталога услуг.

Общий обзор всех тестов проекта: [TESTING.md](./TESTING.md).

## Бэкенд (Jest)

**Расположение:** `backend/src/orders/orders.service.spec.ts`

**Запуск (из корня проекта):**
```bash
cd backend
npm run test -- --testPathPattern=orders
```

**Покрытые сценарии:**
- **submitFromCart** — отправка заказа из корзины:
  - выбрасывает ошибку, если корзина пуста (нет ни товаров, ни услуг);
  - выбрасывает ошибку, если в корзине нет валидных позиций для заказа;
  - создаёт заказ со статусом `PENDING_REVIEW`, если в корзине только услуги (позиции услуг формируются и записываются в `orderServiceItems`).
- **create** — прямой создание заказа по списку товаров:
  - создаёт заказ с корректным расчётом суммы (subtotal, shippingCost, total).

Тесты используют моки `PrismaService`, `CartService`, `UsersService`, `OrderMailService`, `ConfigService` и не требуют реальной БД.

## Фронтенд (Playwright E2E)

**Расположение:** `frontend/e2e/`

**Запуск (из корня проекта):**
```bash
cd frontend
npm run test:e2e
```

Либо с UI:
```bash
npm run test:e2e:ui
```

При первом запуске установите браузеры:
```bash
npx playwright install
```

**Файлы и сценарии:**

1. **orders-checkout.spec.ts** — страницы корзины и оформления заказа:
   - страница корзины `/cart` открывается;
   - страница checkout без `orderId` показывает сообщение об ошибке и ссылку «Вернуться в корзину»;
   - страница checkout с несуществующим `orderId` показывает ошибку загрузки/отсутствия заказа.

2. **catalog-to-cart.spec.ts** — каталоги:
   - страница каталога товаров `/catalog/products` открывается;
   - переход по категории каталога товаров;
   - страница каталога услуг `/catalog/services` открывается.

**Требования для E2E:**
- По умолчанию Playwright поднимает dev-сервер фронтенда (`npm run dev`). Для тестов с реальным API перед запуском нужно поднять бэкенд (`cd backend && npm run start:dev`).
- Переменные окружения (опционально):
  - `PLAYWRIGHT_BASE_URL` или `NEXT_PUBLIC_APP_URL` — URL фронтенда (по умолчанию `http://localhost:3000`).

## Полный сценарий оформления заказа (вручную / будущая автоматизация)

1. **Товары:** пользователь добавляет товары в корзину → корзина → «Отправить на проверку» → `POST /api/v1/orders/submit-from-cart` → заказ в статусе «На проверке» → менеджер в админке подтверждает заказ → клиент переходит по ссылке `/checkout?orderId=...` и оформляет заказ (адрес, способ оплаты).
2. **Услуги:** пользователь выбирает услуги в каталоге услуг → добавляет в корзину → корзина → «Отправить на проверку» → создаётся заказ с `orderServiceItems` (аналогично товарам).

Автоматизация полного сценария с авторизацией и реальным API возможна через Playwright с сохранением токена после логина и подстановкой тестовых данных (категории, товары, услуги) в БД или через API.
