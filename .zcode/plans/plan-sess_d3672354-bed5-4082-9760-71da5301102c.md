# Создание небольшого расчёта прямо из вкладки «Счёт-заказ»/«Смета» договора

## Контекст

Сейчас расчёты создаются только в разделе `/admin/contract-documents/estimates`, а затем вручную прикрепляются к договору. Нужно ускорить типовой сценарий «маленького» расчёта: создание прямо из вкладки «Счёт-заказ»/«Смета» договора через модалку, с автоприкреплением к этому договору. По ответам пользователя: несколько категорий работ (чипы), «Дополнительные виды работ» разрешены, доступно во всех направлениях кроме Мебели.

Ключевые факты архитектуры (всё уже проверено в коде):
- Расчёты — это `ContractEstimatePreset` в JSON-блобе: PUT `/admin/contract-document-packages/estimate-presets` перезаписывает весь список (kind всегда `'REPAIR'` — общий пул всех направлений). **Изменений бэкенда не требуется.**
- Прикрепление к договору — это `form.estimate.selectedPresetIds` + пересчёт через `applyEstimatePresetIdsToPackageForm` (`platform/estimates/applyEstimatePresetIds.ts:406`) + отложенное сохранение пакета.
- Черновик калькулятора — JSON-формат `{v:1, activeCalcId, customItems?, customItemsNoMarkup?, calcs:[{id,name,collapsed,lines:[{itemId,quantity}]}]}`.
- Группа объекта расчёта назначается по адресу: `ensureEstimateObjectGroups` (`platform/estimates/estimateObjectGroupSync.ts`) — заголовок группы = адрес.
- Редактор договора: контроллер `usePackageDocumentEditorController.ts` держит `estimatePresets`/`estimateGroups` и собирает `estimateTabProps` (`usePackageDocumentEditorTabProps.ts:223`).
- Модальный UI — общий `Modal` (Headless UI) + атрибутные стили `data-modal-form` (шаблон: `pages/estimates/modals/EstimateGenerateFromMeasurementModal.tsx`).

## Что делаем (только frontend)

### 1. Новые файлы

**`platform/estimates/packageEstimateQuickCreate.ts`** — чистые функции (тестируемые):
- `buildQuickEstimateDraft({lines, customItems, customItemsNoMarkup})` — черновик формата v1 c одним calc `name: 'Работы'`;
- `buildQuickEstimatePreset({...})` — пресет по образцу `buildEstimateWorkspaceSaveBatch` (`pages/estimates/workspace/estimateWorkspaceSave.ts:103`), но без логики копий/сплитов: id `est_${Date.now()}`, title, `categorySlug`=первая категория, `categoryName` (или «Комплексный расчёт: …»), `calculatorDraft` через `encodePrimaryDraftWithMultiMeta`, `snapshot` через `buildEstimateSnapshot`, `direction` = kind пакета, `crmCustomerId`/`customerName`/`objectAddress` из договора, `createdById` из `useAuth().user.id`, опционально `additionalMarkupPercent`. Переиспользуем `clampWithEllipsis`, `sanitizeEstimatePresetForApi` из `estimateWorkspaceUtils.ts`;
- `resolveQuickEstimateObjectAddress({form, contractEstimateObjectKey, estimateGroups})` — адрес объекта: если объект вкладки — реальная группа, то её заголовок (=адрес), иначе `form.object.objectAddress`;
- `+ packageEstimateQuickCreate.test.ts` (jest, рядом — как `applyEstimatePresetIds.productDirection.test.ts`).

**`platform/hooks/estimate/usePackageEstimateCreateModal.ts`** — состояние модалки и сохранение:
- open/close, name, выбранные категории, строки `{itemId, quantity}` по категориям, кастомные позиции (по образцу воркспейса, хелперы из `platform/estimates/estimateCustomWorkItems.ts`), наценка;
- категории: `useServiceCatalog()` (`@/shared/lib/hooks/useServiceCatalog`); позиции категории: `useServiceCatalogCategory(slug)`;
- предварительный итог считается локально по ценам каталога;
- `save()`: валидация (название, привязанный CRM-заказчик, адрес, ≥1 категория, ≥1 позиция — сообщения как в `estimateWorkspaceSave.ts`) → сборка пресета → `persistEstimateWorkspacePresets([newPreset, ...items], groups)` (переиспользуем — она делает `ensureEstimateObjectGroups`, санитайз и PUT, `pages/estimates/workspace/estimateWorkspacePersist.ts:11`) → `setEstimatePresets`/`setEstimateGroups` в контроллере → автоприкрепление (см. п.3) → закрыть модалку. Если группа нового расчёта (по адресу) не совпадает с зафиксированным объектом уже прикреплённых расчётов — блокируем с понятной ошибкой (иначе `applyEstimatePresetIdsToPackageForm` молча отбросит чужую группу);
- защита: не открывать при `signedDocsLocked`, без `linkedCrmCustomerId`, без адреса — с подсказками.

**`platform/editor/estimateTab/PackageEstimateCreateModal.tsx`** — вью модалки (Modal size xl, alignTop, внутренний скролл):
- поля «Название расчёта»*, readonly «Направление» (= направление договора) / «Заказчик» / «Адрес объекта», «Наценка, %»;
- чипы категорий — переиспользуем `EstimateWorkspaceCategoryPicker` (`pages/estimates/workspace/EstimateWorkspaceCategoryPicker.tsx`);
- по каждой выбранной категории — список работ (name, ед., цена, input количества) и блок «Дополнительные виды работ» (название/ед./цена, чекбокс «без наценки» — как в воркспейсе);
- итог, ошибки валидации, кнопки «Отмена» / «Создать и прикрепить» (`data-admin-mutation`, `data-modal-btn`).

### 2. Кнопка и встройка во вкладку

- `PackageEstimateAttachPanel.tsx`: вторичная кнопка «+ Создать расчёт» в ряду «Прикрепить» (те же guards: `signedDocsLocked`, наличие заказчика);
- `PackageEstimateTabView.tsx`: монтируем `<PackageEstimateCreateModal>`; обновляем футер-подсказку: небольшие расчёты можно создавать здесь, сложные (со связанными экземплярами) — в разделе «Расчёты»;
- `PackageEstimateTab.tsx`: расширяем `PackageEstimateTabProps` (`onOpenEstimateCreate`, `estimateCreate` — props модалки);
- `usePackageDocumentEditorTabProps.ts` + `usePackageDocumentEditorController.ts`: инстанцируем `usePackageEstimateCreateModal` и прокидываем в `estimateTabProps`. Мебель не затрагиваем — её вкладка рендерится другим компонентом (`FurnitureMontageEstimateTabContent`).

### 3. Прикрепление без устаревшего замыкания

`usePackageEstimatePresetHandlers.ts`: расширить `applyEstimatePresetIdsToForm(presetIds, override?: {presets, groups})` — после `setEstimatePresets(новый список)` старое замыкание ещё не видит новый пресет, поэтому прикрепление после создания вызываем с явным override; внутри как сейчас — `applyEstimatePresetIdsToPackageForm` + `schedulePersistDebounced` (сохранение пакета целиком, с серверной проверкой эксклюзивности).

Созданный расчёт — полноценный пресет: появится в разделе «Расчёты» с направлением/заказчиком договора, редактируется в воркспейсе, участвует в конвейере/корзине/аудите как обычно.
