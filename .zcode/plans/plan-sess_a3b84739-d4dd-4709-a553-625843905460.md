# Редизайн страницы /catalog/services по образцу /windows

## Context

Страница `/catalog/services` (скриншот пользователя) — это только хлебные крошки, H1 и плоская сетка мелких карточек с иконками. Страница `/windows` устроена богаче: hero-блок с подзаголовком, описанием и преимуществами, крупные карточки, CTA-блок с кнопками, и весь контент управляется из админки. Цель — довести страницу услуг до того же уровня. По решению пользователя: контент новых блоков **настраивается из админки**; секции: **hero с преимуществами, CTA-блок, «Этапы работы», SEO-текст внизу** + улучшенные карточки категорий.

Ключевые образцы для копирования:
- Публичная страница: `frontend/src/views/windows/ui/WindowsPage/` (WindowsPageView.tsx, WindowsCtaBlock.tsx, WindowsPage.module.css)
- Модель БД: `WindowsPageBlock` в `backend/prisma/schema.prisma:1707`
- SSR: `frontend/src/app/(site)/windows/page.tsx`

**Публичный API** `backend/src/admin/service-catalog/service-catalog-public.service.ts` → `getPublicCatalog()`: вернуть новые поля блока (с безопасным приведением `heroNotes`/`steps` из Json к массивам).

## 2. Frontend: публичная страница

**Типы + серверный fetch** — `frontend/src/shared/api/service-catalog.ts`:
- расширить `ServiceCatalogData.block` новыми полями;
- добавить `fetchServiceCatalog(apiBaseUrl): Promise<ServiceCatalogData | null>` — копия `fetchWindowsSection` (`shared/api/windows/windows.ts:86`): `serverFetch` + `revalidate: 60`, `null` при ошибке.

**SSR роут** — `frontend/src/app/(site)/catalog/services/page.tsx`: как у windows — `export const revalidate = 60`, async-компонент, `initialData = await fetchServiceCatalog(getServerApiBaseUrl())`, `generateMetadata` из `seoTitle`/`seoDescription` блока с текущими захардкоженными текстами как фолбэк.

**Модель** — `views/services/ui/ServiceCatalogPage/hooks/useServiceCatalogPage.ts`: принять `initialData`, передать в `useQuery` (`useServiceCatalog(initialData)`), чтобы сразу рисовать SSR-данные и обновлять на клиенте. `ServiceCatalogPage.tsx` — прокинуть проп.

**Вью** — `views/services/ui/ServiceCatalogPage/ServiceCatalogPageView.tsx` + `.module.css`:
1. **Hero** (grid `1.5fr/1fr`, сворачивается в 1 колонку): подзаголовок, описание, список преимуществ с иконками (акцент `var(--color-accent)`, образец — `.heroNotes` в WindowsPage.module.css), картинка справа.
2. **Карточки категорий** — вертикальные: иконка/картинка сверху крупнее, название (semibold), описание в 2 строки с clamp, бейдж «N видов работ», hover-акцент. Сохранить существующие админ-настройки `cardBackgroundImage` / `cardBackgroundTransparent` + scrim.
3. **«Этапы работы»** — нумерованные шаги 01–04 в адаптивной сетке: заголовок + описание.
4. **SEO-текст** — заголовок + абзац внизу.
5. **CTA** — новый `ServiceCatalogCtaBlock.tsx` (копия паттерна `WindowsCtaBlock.tsx`): настраиваемые цвет фона/текста, фоновая картинка с прозрачностью и fit; кнопки «Заказать звонок» (`callbackModal`) и «Рассчитать стоимость» (`quoteModal`) из `features/forms/context/FormContext`.
6. **Дефолты при пустых полях** (по образцу `DEFAULT_COMPARISON_NOTE` у windows): преимущества «Смета до начала работ / Фиксированные цены в договоре / Гарантия на работы»; этапы «Заявка → Замер и смета → Договор → Выполнение»; CTA «Поможем подобрать услугу» — страница сразу выглядит наполненной в проде, админка переопределяет.
7. CSS: тёмная тема (`:where(html[data-theme='dark'], ...)`) и мобильные брейкпоинты — как в существующих модулях.
