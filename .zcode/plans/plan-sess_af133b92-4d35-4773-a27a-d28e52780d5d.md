# Прощение нарушений режима работы (суперадмин)

## Суть решения
Новая сущность **`WorkDayExcuse`** — отметка «нарушение прощено» за конкретную дату сотрудника и вид нарушения. Факт нарушения в журнале **сохраняется** (видно «30 мин · прощено», комментарий), но:
- не попадает в расчёт удержаний из оклада (`/admin/salary/calculate`, «Моя зарплата», будущие расчёты);
- не учитывается в счётчиках нарушений («Журнал сотрудников» и «Мой рабочий день»).

Покрываются все 4 вида нарушений, за которые сейчас начисляются удержания: **опоздание (LATE), ранний уход (EARLY_LEAVE), автозакрытие (AUTO_CLOSE), прогул (TRUANCY)** — включая сценарий «приложение упало при обновлении, сотрудник опоздал не по своей вине». Прогул — синтетическая строка без записи в БД, поэтому прощение хранится отдельной таблицей по ключу «сотрудник+дата+вид», а не полями в `WorkDay`.

## 1. БД (Prisma)
- `backend/prisma/schema.prisma`: enum `WorkDayExcuseKind { LATE, EARLY_LEAVE, AUTO_CLOSE, TRUANCY }`; модель `WorkDayExcuse` (userId, workDate `@db.Date`, kind, comment `@db.Text?`, createdById?, таймстампы, `@@unique([userId, workDate, kind])`, индексы; связи с User с onDelete Cascade/SetNull — по образцу `WorkDayLeave`, строки ~5272); две реляции в модели User рядом со строками 168–171.
- Миграция `prisma migrate dev --name add_work_day_excuses` + `prisma generate`.

## 2. Бэкенд (NestJS, `backend/src/admin/work-days` + salary)
- **DTO** `CreateWorkDayExcuseDto` в `dto/work-day.dto.ts`: `{ userId, workDate: 'ГГГГ-ММ-ДД', kinds: WorkDayExcuseKind[] (ArrayNotEmpty/@IsIn), comment? }`.
- **Новый сервис** `work-day-excuses.service.ts` (копия паттерна `work-day-leaves.service.ts`):
  - `listExcuses({dateFrom, dateTo, userId, officeId})` c include user/createdBy;
  - `createExcuse(createdById, dto)`: проверка пользователя (существует/активен), валидация даты, upsert по `[userId, workDate, kind]` для каждого вида (повторная отметка обновляет комментарий); затем уведомление сотруднику;
  - `deleteExcuse(id)` — отзыв прощения; `mapExcuse` — даты в ISO.
- **Контроллер** `work-days.controller.ts`, всё `@Roles(UserRole.SUPER_ADMIN)`, блок рядом с leaves (до generic-маршрутов): `GET excuses`, `POST excuses`, `DELETE excuses/:id`.
- **Модуль**: сервис в providers `work-days.module.ts`.
- **Уведомление сотруднику**: `WorkDayNotifyService.onExcuseGranted(...)` — push через `adminBellPush.notifyUsers([userId], 'work_day', { title: 'Нарушение прощено', body: «Опоздание за 20.10.2026 не учитывается при расчёте», url: '/admin/crm/my-work-day' })` по образцу `onRequestReviewed`.
- **Журнал** (`work-day-journal.service.ts` + `work-day-journal-rows.ts`): в `attachRequests` подгрузить прощения за период (map по `userId|дата`), добавить поле `excuses: WorkDayExcuseBadge[]` (`{id, kind, comment, createdAt}`) во все типы строк — и записи, и синтетические прогулы. Используется и журналом, и «Моим рабочим днём», и расчётом прогулов.
- **Сводка** `summarizeMyRows`: `lateDays`/`earlyLeaveDays`/`autoClosedDays`/`truancyDays` не считают прощённые.
- **Удаление записи** `deleteWorkDay`: заодно удалять прощения видов LATE/EARLY_LEAVE/AUTO_CLOSE за эту дату (TRUANCY оставляем — день может стать прогулом).
- **Зарплата** `salary-employee-salaries.service.ts`: один запрос `workDayExcuse.findMany` за `[from, penaltyUntil]`, Set `` userId|дата|вид ``; пропускать прощённые события в трёх блоках расчёта (опоздания/ранние уходы, автозакрытия, прогулы) — из расшифровки `deductions[]` они просто исчезают. Подтверждённые расчёты — снапшоты в JSON, задним числом не пересчитываются (так и осталось бы при любом решении).

## 3. Фронтенд (Next.js)
- **API-клиент** `shared/api/crm/admin-work-days.ts`: типы `WorkDayExcuseKind`, `WorkDayExcuse`, `WorkDayExcuseBadge`; поле `excuses?` в типах строк журнала; функции `getWorkDayExcuses` / `createWorkDayExcuse` / `deleteWorkDayExcuse`.
- **Утилиты** `work-days-display.utils.ts`: `workDayExcuseLabel(kind)`, `hasWorkDayExcuse(row, kind)`, `unexcusedViolations(row)`; `workDayRowClassName` — подсветка строки (красная у опоздания и т.п.) только по непрощённым нарушениям.
- **Журнал** `/admin/crm/work-days`:
  - хук `useWorkDaysPage`: `canManageExcuses` (= SUPER_ADMIN), загрузка списка прощений и мутации по образцу leaves; статистика исключает прощённые + чип «Прощённых нарушений: N» (показывается при >0);
  - в ячейках «Опозд.»/«Ранний уход»/статусе и бейдже «Прогул» — метка «прощено» (title = комментарий);
  - кнопка «Простить нарушение» в колонке действий (только суперадмин; видна, если на строке есть непрощённое нарушение; работает и для строк-прогулов);
  - новое модальное окно `WorkDayExcuseModal.tsx` (по образцу `WorkDayLeaveModal`): сотрудник и дата из строки (только чтение), чекбоксы нарушений этой строки (отмечены непрощённые), необязательный комментарий;
  - блок чипов прощённых над таблицей с крестиком отмены + ConfirmModal (по образцу отпусков); аналогичные элементы в мобильных карточках.
- **«Мой рабочий день»** `MyWorkDayPageView.tsx`: метка «прощено» рядом с опозданием/ранним уходом в карточке текущего дня (~строка 288), таблице истории (~546) и мобильных карточках (~686), у бейджей «Прогул» (~492, ~584). Счётчики приходят с бэкенда уже без прощённых.

## 4. Проверка
- Бэкенд: `npx prisma migrate dev --name add_work_day_excuses` (локальная БД), `npm run type-check`, `npm run build`.
- Фронтенд: `npm run validate` (type-check + lint + format + архитектура).

Примечание: уже отправленные уведомления об опоздании не отзываются; комментарий прощения необязателен (как у отпусков/заявок).
