# Украшения публичного сайта: раздел в админке + новогодний снег

## Context

Нужна возможность управлять «украшениями» публичного сайта (601270.ru) из админки. Первое украшение — новогодний эффект падающего снега, включаемый тумблером. Проект — монорепозиторий: бэкенд NestJS 11 + Prisma 5 (PostgreSQL), фронтенд Next.js 16 App Router (React 19, CSS Modules). Готовый образец для копирования — ветка `site-public` (настройка «Шапка публичного сайта»): Prisma-модель → публичный `GET /site-public/config` → контекст `SitePublicConfigContext` → рендер в `SiteLayout`; админка — страница в `/admin/settings/...` + регистрация ресурса доступа.

Архитектура: реестр украшений в коде бэкенда (код → название/описание), состояние (вкл/выкл + необязательный период показа) — в таблице `site_decorations`. Строки синхронизируются с реестром при чтении, поэтому новые украшения появляются в админке автоматически. Доступ — SUPER_ADMIN (как у соседних настроек внешнего вида публички).

## Бэкенд

1. **Модель** — `backend/prisma/schema.prisma` (рядом с `SitePublicConfig`, ~строка 3251):
   ```prisma
   /// Украшения публичного сайта (снег и т.п.). Строки синхронизируются с реестром в site-public модуле.
   model SiteDecoration {
     id        String    @id @default(cuid())
     code      String    @unique // 'new-year-snow'
     isActive  Boolean   @default(false)
     startsAt  DateTime? // необязательный период показа
     endsAt    DateTime?
     updatedAt DateTime  @updatedAt
     @@map("site_decorations")
   }
   ```
   Миграция: `cd backend && npx prisma migrate dev --name site_decorations` (БД `localhost:5432/territory`; если не запущена — создать папку миграции вручную в стиле Prisma `CREATE TABLE "site_decorations" ...` + unique index по `code`).

2. **Реестр** — новый `backend/src/site-public/site-decorations.registry.ts`: массив `{ code: 'new-year-snow', title: 'Новогоднее украшение — снег', description: '...' }` + тип.

3. **DTO** — `backend/src/site-public/dto/update-site-decoration.dto.ts`: `@IsBoolean() isActive?`, `@IsOptional() @IsDateString() startsAt/endsAt?: string | null` (глобальный ValidationPipe whitelist).

4. **Сервис** — расширить `site-public.service.ts`:
   - `getPublicConfig()` — добавить `decorations: [{ code, startsAt, endsAt }]` (только активные строки; ISO-строки).
   - `listAdminDecorations()` — upsert недостающих строк из реестра, вернуть список с метаданными реестра.
   - `updateAdminDecoration(code, dto)` — проверка кода по реестру (`NotFoundException`), `isActive` + даты (`null` — сброс, `undefined` — не трогать).

5. **Контроллер** — новый `backend/src/site-public/site-decorations-admin.controller.ts`: `@Controller('admin/site-decorations')`, `JwtAuthGuard + RolesGuard`, `@Roles('SUPER_ADMIN')`, `GET ''` и `PATCH ':code'` (по образцу `site-public-admin.controller.ts`). Подключить в `site-public.module.ts`.

## Фронтенд — публичка

6. **API-тип** — `frontend/src/shared/api/site-public.ts`: добавить `decorations?: Array<{ code: string; startsAt: string | null; endsAt: string | null }>`.

7. **Контекст** — `frontend/src/shared/lib/contexts/SitePublicConfigContext.tsx`: поле `decorations` в состоянии (default `[]`) + экспорт хелпера `useActiveSiteDecorations(): string[]` — фильтрует по периоду (`Date.now()` в пределах startsAt/endsAt, если заданы).

8. **Виджет украшений** — новый `frontend/src/widgets/site-decorations/` (+ `index.ts`):
   - `SiteDecorations/SiteDecorations.tsx` — клиентский компонент, читает активные коды, рендерит `<Snowfall />` при `'new-year-snow'`.
   - `Snowfall/Snowfall.tsx` + `Snowfall.module.css` — canvas-эффект снега: `position: fixed; inset: 0; pointer-events: none; z-index: 9990` (ниже чата 9998/PWA 9999), `aria-hidden`; ~100–140 снежинок (плотность от ширины экрана), разные размер/скорость/покачивание; `requestAnimationFrame` с паузой при `document.hidden`, обработка resize и devicePixelRatio, полная очистка при unmount; при `prefers-reduced-motion: reduce` не рендерится. Только self-hosted код — CSP не затрагивается.
   - Смонтировать `<SiteDecorations />` в `frontend/src/widgets/site-layout/SiteLayout/SiteLayout.tsx` (рядом с оверлеями, после `<PWAUpdatePrompt />`) — есть на всех публичных страницах, в админке отсутствует.

## Фронтенд — админка

9. **API-клиент** — новый `frontend/src/shared/api/admin-site-decorations.ts`: `getAdminSiteDecorations()`, `updateAdminSiteDecoration(code, data)` (Bearer из `localStorage.admin_token`, по образцу `admin-site-public.ts`).

10. **Страница** — `frontend/src/app/admin/settings/site-decorations/page.tsx` → `frontend/src/views/admin/Settings/site-decorations/SiteDecorationsSettingsPageView.tsx` + `.module.css` (стили по образцу `AuthSection.module.css`, CSS-переменные `--admin-*`):
    - заголовок «Украшения сайта», проверка `user?.role === 'SUPER_ADMIN'`;
    - карточка на каждое украшение: название, описание, чекбокс «Включено», необязательные `datetime-local` «Начало/Окончание показа» (пусто → `null`; конвертация ISO ↔ local);
    - одна кнопка «Сохранить» с `data-admin-mutation` (PATCH по каждому изменённому украшению), тост успех/ошибка, ссылка «Открыть публичку →».

11. **Регистрация раздела** (4 синхронные точки + 2 списка):
    - `backend/src/admin/admin-access/resources.config.ts` и `frontend/src/shared/config/admin-resources.ts`: `{ id: 'admin.settings.site-decorations', label: 'Украшения сайта', path: '/admin/settings/site-decorations' }` (после `admin.settings.public-header`);
    - `backend/src/admin/admin-access/admin-resource-tree.config.ts` и `frontend/src/shared/config/admin-resource-tree.ts`: `'admin.settings.site-decorations': 'admin.settings'`;
    - пункт в сайдбаре: `frontend/src/widgets/admin/Sidebar/AdminSidebar.tsx` (после «Шапка публичного сайта»);
    - ссылка в хабе: `frontend/src/views/admin/Settings/hub/SettingsHubPageView.tsx`.
    - В `role-default-resources.config.ts` не добавлять (SUPER_ADMIN и так имеет доступ, как у public-header).

## Верификация

- Бэкенд: применить миграцию, `cd backend && npm run build` (tsc без ошибок).
- Фронтенд: `cd frontend && npm run build` (или `npx tsc --noEmit` + ESLint изменённых файлов).
- Вручную в браузере (browser-use): поднять dev-серверы (`npm run dev`, порты 3001/3000) → в админке `/admin/settings/site-decorations` включить снег, сохранить → на публичке `/` проверить падающий снег (canvas, не мешает кликам), в админке снега нет; выключить — снег исчезает после перезагрузки. Если логин в админку недоступен — включить тумблер напрямую в БД и проверить публичку.
