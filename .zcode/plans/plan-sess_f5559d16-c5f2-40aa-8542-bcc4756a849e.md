# Скидки в пакете документов «Ремонт»: % и рубли, своя скидка по Д/с, автопересчёт заказ-нарядов

## Что уже есть (важно)

Процентная скидка **на уровне договора уже реализована**: поле `contract.discountPercent` («Скидка на работы», вкладка «Данные», `PackageDataContractObjectSection.tsx:167-186`). Она уже применяется к итогам сметы (подвал «Итого со скидкой»), ко всем Д/с, **к каждой позиции и итогам заказ-нарядов** (основной, по Д/с, итоговый, по мастерам — `workOrderHtml.ts:52-123`, `usePackageFinalEstimateWorkOrders.ts:221-303`), к сводке оплат, з/п и расчётам с мастерами (бэкенд-порты). Пункты 1(частично) и 3 задачи в части «%» уже работают.

**Чего нет:** ввода скидки в рублях; отдельной скидки у каждого Д/с (сейчас Д/с наследуют договоровую).

## Моё мнение по вопросу «рубли → %» (из задачи)

Подход правильный, и в этой архитектуре — фактически единственный безболезненный: весь расчёт (фронт + бэкенд, включая raw SQL `formData->'contract'->>'discountPercent'` в расчётах с мастерами) построен на одном процентном коэффициенте. Пересчёт «рубли → %» в одной точке сохраняет согласованность всех потребителей автоматически; уменьшение каждой позиции на вычисленный % математически равно пропорциональному распределению рублёвой скидки по строкам. Оговорки, которые закладываю в реализацию:

1. **Рубли — источник истины, % — производное.** При изменении сметы/Д/с % пересчитывается (иначе «скидка 10 000 руб.» перестанет быть 10 000 после правки сметы).
2. Точность: % хранится с 6 знаками (копеечная точность), заказ-наряды считаются в копейках — расхождение Σ позиций с «итог − скидка» максимум 1–2 копейки на округлении строк.
3. База пересчёта: для договора — итог сметы без скидки; для Д/с — итог добавляемых работ Д/с (исключения не дисконтируются, как и сейчас).
4. Рублей больше базы → эффективный % = 100.
5. В печатных формах пишем и сумму, и %: «Скидка: 10 000 руб. (≈12,35%)».

Решения, подтверждённые пользователем: скидка Д/с **замещает** договорную (пусто → наследование); ввод скидки сметы — на «Данных» **и** на вкладке «Смета».

## Модель данных (formData, без миграций Prisma)

```ts
// PackageContractBlock (types.ts:73)
discountPercent: string;                  // остаётся каноническим эффективным % (его читает бэкенд SQL)
discountType?: 'PERCENT' | 'AMOUNT';      // default 'PERCENT' (легаси-данные)
discountAmount?: string;                  // рубли при AMOUNT — источник истины

// PackageAddendumSlotEstimateBlock (types.ts:226)
discountType?: 'INHERIT' | 'PERCENT' | 'AMOUNT';  // default 'INHERIT'
discountPercent?: string;                 // эффективный % слота (derived при AMOUNT)
discountAmount?: string;                  // рубли
```

`defaults.ts` + `normalize.ts`: дефолты для новых полей; идемпотентная синхронизация производных % при загрузке (в т.ч. для старых пакетов).

## Ядро расчёта — `packageContractDiscount.ts` (новые помощники)

- `parseDiscountAmountRub(raw)`; `deriveDiscountPercentFromAmount(amountRub, base)` → clamp 0..100, формат с 6 знаками, запятая.
- `resolveContractDiscount(form)` → { mode, percent, amountRub, base } (base = `estimate.snapshot.total`).
- `resolveAddendumSlotDiscountPercent(form, slotIndex0)`: PERCENT → свой %; AMOUNT → derived от `slot.snapshot.total`; INHERIT/пусто → договорный %.
- `syncContractDiscountDerivedFields(form)` — пересчёт `contract.discountPercent` при AMOUNT (и аналогично для слотов); вызывается из: обработчика полей, `applyEstimatePresetIdsToPackageForm` / `applyEstimatePresetIdsToAddendumSlot` (правка сметы), normalize при загрузке.

## Фронтенд

1. **UI «Данные»** (`PackageDataContractObjectSection.tsx`): поле «Скидка на работы» → сегмент «% | руб.» + значение + подсказка («≈12,35%» / итог со скидкой). Режим «руб.» доступен для ремонтоподобных и товарных направлений; «Мебель» — только %. Блокировка после подписания — как сейчас.
2. **UI «Смета»**: дублирующий ввод скидки рядом с итогами листа (`PackageEstimateTab`/`PackageEstimateMergedSheet`), синхронизирован с теми же полями contract.
3. **UI Д/с** (`PackageAddendumEstimateBlockView`/AdditionalWorksSection): «По договору (5%) | Своя: [%|руб.] + значение». Блокируется при статусе слота SIGNED/PAID (через `patchAddendumSlotField` с guard).
4. **Обработчики**: `usePackageContractFieldHandlers.ts` (сейчас строки 74-86) — пересчёт derived % + полей суммы договора при вводе %/руб./типа; то же для полей слота.
5. **Подвалы печатных форм**: `buildEstimateDiscountTotalsBlockHtml` (`packageEstimateDocPrintEmbedHtml.ts:202`) принимает {percent, amountRub} → «Скидка: 10 000 руб. (≈12,35%)»; смета-лист, печать Д/с (`packageFormForTemplate.ts:239-286` — подвал Д/с берёт скидку слота, не договора).
6. **Заказ-наряд по Д/с** (`packageFormForTemplate.ts:416-443`): вместо `form.contract.discountPercent` — процент слота (в ремонтной ветке и в `buildWorkOrderHtmlForInstallationSchedule` для записей графика монтажа, привязанных к Д/с).
7. **Сводка оплат**: `computeRepairLikePayableBreakdown` (`packagePaymentTotals.ts:56-76`) — процент слота для каждой строки Д/с; «Скидка» в сводке хаба (`usePackagePaymentsSummaryBreakdown.ts`, `PackageContractPaymentsHubSummarySection.tsx`) — по слотам.
8. **Итоговая смета/итоговый заказ-наряд**: `finalEstimateSummary.ts` — строки несут вклады по источникам (`main`, `addendum-1..5`; включено−исключено в рамках источника, clamp ≥0 по источнику); `usePackageFinalEstimateWorkOrders.ts` — фактор скидки по источнику строки; итоговые суммы и листы по мастерам пересчитываются автоматически. Отображение в `PackageFinalEstimateTab.tsx`.
9. Каскад заказ-нарядов сметы/договора уже работает через `contract.discountPercent` — не меняется (кроме отображения % в подвалах).
10. Мелочи: `contractPlaceholders.ts` (+`{{contract.discountAmountRub}}`), `package-version-key-moments.ts` (метки новых полей), «Скидка» в списках договоров — без изменений (читают эффективный %).

## Бэкенд (паритет, «Изменения формул — синхронно с фронтендом»)

1. `installer-accrual.ts` — расчёт по источникам с фактором скидки источника (аналог фронтендового итогового заказ-наряда); парсинг новых полей слотов; derive для AMOUNT.
2. `installer-settlements.service.ts` — в raw SQL выбора кандидатов добавить поля скидки слотов (`formData->'addendumSlots'->n->'discountType'/'discountPercent'/'discountAmount'`), прокинуть в accrual.
3. `salary-contracts-sync.service.ts` — `collectSignedAddenda`/`snapshotTotalAfterDiscount`: скидка слота для Д/с, договорная (AMOUNT-aware) для основной сметы.
4. `package-list-pipeline-status.ts` — `computePayableBreakdown`: ремонтные Д/с со скидкой слота; договорный % с учётом AMOUNT (база есть в formData).

## Объём направлений

По задаче — «Ремонт»: полная реализация (договор + Д/с + заказ-наряды + сводки + бэкенд). Товарные направления получают режим «руб.» на договорной скидке (та же семантика, что % сегодня); собственная скидка Д/с для них не показывается в UI (наследование, как сейчас). Мебель — без изменений (%).

## Тесты (vitest, по образцу существующих)

- `packageContractDiscount`-хелперы: parse/derive/clamp/формат; sync derived при изменении базы.
