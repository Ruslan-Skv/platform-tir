# Удалённая помощь суперадмина (WebRTC-трансляция экрана + управление)

## Контекст

Суперадмину нужен инструмент, чтобы дистанционно помогать сотрудникам админки (менеджерам, замерщикам и т.д.) в работе с приложением: видеть их экран и удалённо нажимать/вводить текст в окне приложения. Выбранный подход — **встроенный WebRTC** (без сторонних программ): пользователь подтверждает доступ и делится экраном через `getDisplayMedia`, суперадмин смотрит трансляцию и управляет вводом через WebRTC DataChannel. Сигналинг — через socket.io по образцу существующего `messenger.gateway.ts`. Аудитория — сотрудники админ-панели (у них уже есть presence). Согласие пользователя и журнал сессий обязательны.

Известные ограничения браузеров (прямо скажем в UI): управление работает только внутри окна приложения (вкладки/окна, которым пользователь делится), а не всей ОС; файловые диалоги и часть нативных контролов не управляемы.

## Сценарий (flow)

1. **Приглашение**: суперадмин на `/admin/remote-help` выбирает онлайн-сотрудника (из presence) → `POST /admin/remote-help/invites` → сессия `PENDING` → сокет-событие `help:invite` в комнату `user:{id}`.
2. У сотрудника во всех открытых вкладках админки всплывает модалка «Суперадмин запрашивает доступ к экрану» [Разрешить]/[Отклонить]. Клик «Разрешить» — это user gesture: сразу вызывается `getDisplayMedia()` (подсказка делиться вкладкой/окном приложения), затем `POST accept` → `ACTIVE`, далее WebRTC offer/answer/ICE через сокет.
3. **Просмотр + управление**: у суперадмина появляется видео; тумблер «Управление» включает пересылку событий мыши/клавиатуры через DataChannel; на стороне сотрудника события воспроизводятся в его странице (клики по координатам, ввод текста), плюс красный указатель «куда нажать».
4. Обратный сценарий: у сотрудника кнопка «Запросить помощь» → `POST /requests` → событие `help:request` суперадминам (комната `helpers`) → тост со ссылкой; суперадмин «Принимает» (`claim`) → как в п.1.
5. Завершение любой стороной, по кнопке Stop Sharing в браузере, по дисконнекту сокета или по таймауту `PENDING/REQUESTED` (90 c → `EXPIRED`). Всё пишется в БД (кто, кого, когда, статус).

## Бэкенд (`backend/src/admin/remote-help/` — новый модуль по паттерну messenger)

**Prisma** (`prisma/schema.prisma` + миграция `npx prisma migrate dev --name remote_help_session`):
- enum `RemoteHelpSessionStatus { REQUESTED PENDING ACTIVE ENDED DECLINED CANCELLED EXPIRED }`
- модель `RemoteHelpSession` (`@@map("remote_help_sessions")`): `userId`, `adminId?`, `status`, `createdAt/respondedAt?/startedAt?/endedAt?`, `endReason?`, связи на `User` (`RemoteHelpSessionUser/Admin`), индексы `[userId, createdAt]`, `[adminId]`, `[status]`.

**Файлы модуля**: `remote-help.module.ts`, `remote-help.controller.ts`, `remote-help.service.ts`, `remote-help.gateway.ts`, `dto/`. Зарегистрировать в `backend/src/admin/admin.module.ts`.

**Gateway** (`@WebSocketGateway({ namespace: '/remote-help' })`, CORS как в `messenger.gateway.ts:18-32`): JWT-аутентификация в `handleConnection` (копия `messenger.gateway.ts:48-72`), комнаты `user:{id}` + `helpers` для SUPER_ADMIN. События:
- клиент→сервер `help:signal { sessionId, data }` — проверка участия в ACTIVE-сессии, relay counterpart'у;
- сервер→клиент: `help:invite`, `help:invite:resolved` (все вкладки сотрудника гасят модалку), `help:request`, `help:signal`, `help:ended`;
- `handleDisconnect` → завершение ACTIVE-сессий пользователя с emit `help:ended`.

**REST** (`@Controller('admin/remote-help')`, JwtAuthGuard + RolesGuard):
- `POST /invits {userId}` и `POST /sessions/:id/claim`, `POST /sessions/:id/cancel`, `GET /sessions` (история с фильтрами), `GET /pending` — `@Roles('SUPER_ADMIN')`, `@Throttle` на приглашения;
- `POST /requests`, `POST /sessions/:id/accept`, `/decline`, `/end`, `GET /ice-servers` — `@Roles(...ADMIN_ROLES)` с проверками владения сессией в сервисе (сотрудник — только свою, суперадмин — только свою invite/claim);
- `GET /ice-servers` отдаёт STUN по умолчанию + TURN из env (`TURN_URL`, `TURN_USERNAME`, `TURN_CREDENTIAL` — добавить в `.env.example`; опционально закомментированный сервис coturn в `docker-compose.infra.yml`).

**Конфиг доступа**: добавить `/api/v1/admin/remote-help` в `ADMIN_API_SKIPPED_PREFIXES` (`common/config/admin-api-route-resources.config.ts:6`) — как presence, роли проверяются в контроллере. Ресурс страницы `admin.remote-help` добавить в `backend/src/admin/admin-access/resources.config.ts` и **не** включать в `role-default-resources.config.ts` (тогда раздел виден только SUPER_ADMIN, т.к. он обходит всё).

## Фронтенд

**API-клиент** `frontend/src/shared/api/admin-remote-help.ts`: REST-обёртки над `apiFetch` + `connectRemoteHelpSocket()` по образцу `shared/api/messenger/messenger-socket.ts`.

**Фича** `frontend/src/features/remote-help/`:
- `lib/rtc-peer.ts` — создание `RTCPeerConnection` с ICE из `/ice-servers`, обмен offer/answer/ICE через `help:signal`, DataChannel `control`;
- `lib/control-capture.ts` — захват событий мыши/колеса/клавиатуры на контейнере видео (нормализация координат с учётом `object-fit: contain`, троттлинг mousemove), отправка в DataChannel;
- `lib/control-replay.ts` — воспроизведение: `document.elementFromPoint` + dispatch Pointer/Mouse events, ввод текста через native setter для `input/textarea` (чтобы React ловил onChange) и `execCommand('insertText')` для contenteditable/TipTap, Backspace/Enter/Tab, `scrollBy` для wheel, оверлей-указатель;
- `components/RemoteHelpReceiver.tsx` + `hooks/useRemoteHelpReceiver.ts` — глобальный приёмник: модалка приглашения (клик «Разрешить» → `getDisplayMedia` синхронно в жесте → REST accept → peer), баннер «Идёт сеанс помощи • Завершить», авто-конец по `track.onended`; для SUPER_ADMIN — тост о входящем `help:request`; для остальных ролей — кнопка «Запросить помощь» с индикатором ожидания. Смонтировать в `frontend/src/app/admin/AdminLayoutClient.tsx` рядом с `<AdminPresenceHeartbeat />` (строка ~185).

**Страница суперадмина** `/admin/remote-help`:
- тонкая страница `frontend/src/app/admin/remote-help/page.tsx` → `frontend/src/views/admin/RemoteHelp/RemoteHelpPage.tsx` (+ hook + view + `*.module.css`) по канону `views/admin/Users`;
- панели: онлайн-сотрудники (поллинг `GET /admin/presence/online`, как `AdminOnlineAvatars`) с кнопкой «Подключиться»; входящие запросы с «Принять»; просмотрщик активной сессии (видео, тумблер «Управление», «Завершить», fullscreen, таймер, ФИО и статус); история сессий через `shared/ui/admin/DataTable`.

**Регистрация раздела**:
- сайдбар: пункт «Удалённая помощь» (`icon: '🖥️'`, `resourceId: 'admin.remote-help'`) рядом с «Мессенджер» (`widgets/admin/Sidebar/AdminSidebar.tsx:565`);
- `ADMIN_RESOURCES` в `frontend/src/shared/config/admin-resources.ts` (+ дерево `admin-resource-tree.ts` при необходимости).

**Заголовки/CSP**: изменений не требуется — `getDisplayMedia` не регулируется `camera=()` из Permissions-Policy, поток вешается через `srcObject`, `wss://` до API уже разрешён в connect-src.

## Порядок работ

1. Prisma-модель + миграция → 2. бэкенд-модуль (service → controller → gateway → регистрация + skipped-prefix + resources.config) → 3. фича remote-help на фронтенде (lib → receiver) → 4. админ-страница + сайдбар + ресурсы → 5. env/доки (`.env.example`, короткий `docs/REMOTE-HELP.md` с описанием TURN и ограничений).

## Проверка

- Бэкенд: `npm run validate` (type-check + lint + check-architecture) в `backend/`; миграция применяется чисто.
- Фронтенд: type-check/lint/build в `frontend/`.
- Ручной E2E в двух браузерах: поднять backend+frontend, `npm run create-super-admin`; залогиниться суперадмином и тестовым сотрудником (напр. MANAGER) → инвайт из `/admin/remote-help` → «Разрешить» с выбором вкладки приложения → видео у суперадмина → включить «Управление», кликнуть по кнопке и ввести текст на экране сотрудника → убедиться, что ввод применился → завершить с обеих сторон, проверить статусы/историю; проверить отказ, таймаут, остановку шаринга через браузерную панель, «Запросить помощь» от сотрудника.
- Не трогать существующие изменённые файлы `frontend/public/workbox/*` и ничего не коммитить без запроса.
