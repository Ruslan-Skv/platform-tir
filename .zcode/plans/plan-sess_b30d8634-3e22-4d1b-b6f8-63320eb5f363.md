# Уведомления удалённой помощи (запрос помощи / запрос на подключение)

## Контекст

Сейчас уведомление о событиях удалённой помощи живёт только в реальном времени: тост суперадмину и модалка сотруднику доставляются socket.io в открытые вкладки. Если получатель не в админке (или вкладка не открыта) — событие теряется. Нужно встроить события в существующую систему уведомлений проекта: колокольчик в шапке админки, Web Push (PWA) и внешние каналы (email/Telegram/MAX), следуя готовым паттернам (мессенджер → персональные bell-события + `notifyUsers`; поддержка → broadcast + внешний канал).

События:
- **«Запрос помощи»** (сотрудник → `POST /requests`): уведомить всех активных суперадминов.
- **«Запрос на подключение»** (суперадмин → `invites`/`claim`): уведомить конкретного сотрудника.

## Бэкенд

### 1. Web Push — новые события (`backend/src/bell-push/admin-bell-push.service.ts`)
- Добавить в `AdminBellPushEvent`: `'remote_help_request'`, `'remote_help_invite'`.
- В `isEventEnabled` — `return true` для обоих (стиль `messenger_message`/`kanban_card`: всегда включены, регулируются только общим `desktopNotifications`; без новых `notifyOn*`-флагов ⇒ **без миграции настроек**).

### 2. Call sites (`backend/src/admin/remote-help/remote-help.service.ts`)
- `createRequest()`: после `emitRequest` — найти активных SUPER_ADMIN (`prisma.user.findMany`) и `adminBellPush.notifyUsers(ids, 'remote_help_request', { title: 'Запрос удалённой помощи', body: '<Имя> просит помочь в работе с приложением', url: '/admin/remote-help', tag: 'remote-help-request-<id>' })`; плюс внешний канал: `externalNotifySettings.getChannelsForEvent('remote_help')` → `externalNotify.send(...)` (стиль `support-chat.service.ts:195`).
- `createInvite()` и `claim()`: `notifyUsers([userId], 'remote_help_invite', { title: 'Запрос на подключение к экрану', body: '<Имя суперадмина> просит доступ к вашему экрану', url: '/admin', tag: 'remote-help-invite-<id>' })`.
- Внедрить `BellPushModule`, `ExternalNotifyModule` в `remote-help.module.ts`; ФИО — из уже включённых `session.user/admin` (фолбэк на email).

### 3. Bell-фид (support-стиль, без новой таблицы): `backend/src/admin/notifications/`
- `admin-bell-remote-help-feed.service.ts`: `listForUser(userId, role, limit)` — за 14 дней: для SUPER_ADMIN — сессии `REQUESTED` («<Имя> запрашивает помощь», `href=/admin/remote-help`); для остальных — свои `PENDING` («<Имя суперадмина> просит доступ к вашему экрану», `href=/admin`). Разрешённые исчезают из фида сами (как OPEN-диалоги поддержки). Форма items — как у `admin-bell-messenger-feed.service.ts` (`{id, kind, kindLabel, title, message, href, occurredAt}`).
- Контроллер: `GET admin/notifications/bell/remote-help` (по образцу `bell/messenger`, `admin-notifications.controller.ts:298`) + провайдер в `admin-notifications.module.ts`.

### 4. Внешний канал `remote_help` (email/TG/MAX)
- Prisma: 3 `Json?`-колонки `remoteHelpNotifyEmails/TelegramIds/MaxIds` в `ExternalNotifySettings` + миграция.
- `external-notify-settings.service.ts` + админ-копия `admin/external-notify/admin-external-notify.service.ts` (union, `getChannelsForEvent`, `mapSettings`, `updateSettings`) + поле в `UpdateExternalNotifySettingsDto`.
- Фронтенд-UI: `views/admin/Settings/notifications/LeadNotificationChannelsSection.tsx` — ключ в `ChannelKey` + запись в `EVENTS_BY_TAB` (таб «Прочее») + `pickExternal`/`buildExternalPatch`; тип в `shared/api/admin-external-notify.ts`.

### 5. TTL запросов: `remote-help.service.ts`
`REQUESTED` живёт 10 минут (сейчас 90 с — внешний канал не успевает), `PENDING` остаётся 90 с: разделить константы в `expireStale()`.

## Фронтенд

### 6. Колокольчик (`widgets/admin/Header/`)
- `admin-header-notifications.utils.ts`: тип `'remoteHelp'` в `AdminBellNotificationType`; `isBellTypeEnabled` → всегда true; кейс в `buildDesktopNotification`.
- `shared/api/admin-notifications.ts`: `getAdminBellRemoteHelp(limit)` → `GET /admin/notifications/bell/remote-help`.
- `AdminHeader.tsx` (`loadAllNotifications`): добавить запрос в `Promise.allSettled`, замапить в bell-item (текст/ссылка приходят из фида); фид опрашивается для всех ролей — состав сервер определяет по роли. Дисмисс/история работают автоматически по ключу `remoteHelp:<sessionId>`.

### 7. Восстановление пропущенных приглашений (`features/remote-help/hooks/useRemoteHelpReceiver.ts`)
Раз в 30 с (когда нет показанной модалки/активной сессии) перечитывать `getMyRemoteHelpSession()` и прогонять через `applySession` — модалка восстановится, в т.ч. после клика по bell-item.
