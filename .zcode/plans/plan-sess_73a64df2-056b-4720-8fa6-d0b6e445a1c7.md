# Функционал скриншотов в админке (захват через приложение, раздел «Скриншоты», TTL 3 дня)

## Context
Приложение активно дорабатывается, ошибки удобнее исправлять по скриншотам, но не все админы умеют делать их средствами ОС. Нужен простой механизм: кнопка в админке → снимок экрана → сохранение на сервере. Скрины видит суперадмин (все) и автор (свои); их можно скачать и удалить; через 3 дня после создания удаляются автоматически и безвозвратно.

Захват — через **Screen Capture API (`getDisplayMedia`)**: точный снимок реального экрана/вкладки, без новых зависимостей; механизм уже используется в «Удалённой помощи» и «Онлайн-собраниях». Админ жмёт кнопку 📷 в шапке → выбирает источник в окне браузера (текущая вкладка предвыбрана) → кадр снимается → модалка предпросмотра с комментарием → «Сохранить».

## Backend (NestJS + Prisma)

### 1. Модель и миграция
`backend/prisma/schema.prisma` — новая модель (образец: `WaybillTaskAttachment`):
```prisma
model AdminScreenshot {
  id        String   @id @default(cuid())
  fileName  String                     // screenshot-<дата>-<rand>.png
  fileUrl   String   @default("")      // /uploads/screenshots/<file>
  fileSize  Int      @default(0)
  mimeType  String   @default("image/png")
  width     Int?
  height    Int?
  comment   String?  @db.VarChar(500)
  pageUrl   String?  @db.VarChar(500)  // где снят скрин (маршрут админки)
  authorId  String   @map("author_id")
  author    User     @relation(fields: [authorId], references: [id], onDelete: Cascade)
  createdAt DateTime @default(now()) @map("created_at")
  expiresAt DateTime @map("expires_at") // createdAt + 72ч
  @@index([expiresAt])
  @@index([authorId])
  @@map("admin_screenshots")
}
```
+ обратная связь `screenshots AdminScreenshot[]` в `model User`. Миграция: `npx prisma migrate dev --name admin_screenshots`.

### 2. Модуль `backend/src/admin/screenshots/` (включить в `admin.module.ts`)
- **controller** `@Controller('admin/screenshots')`, `@UseGuards(JwtAuthGuard, RolesGuard)`, `@Roles(...ADMIN_ROLES)`:
  - `GET /` — список (`@SkipThrottle`): SUPER_ADMIN — все (+опц. `?authorId=`), остальные — только свои (`authorId: req.user.id`); всегда фильтр `expiresAt > now`; в ответе данные автора.
  - `POST /` — загрузка: `FileInterceptor('file')` c multer `diskStorage` → `uploads/screenshots` (паттерн `knowledge.controller.ts`), лимит 15 МБ, whitelist MIME `image/png|jpeg|webp`, имя файла через `crypto.randomUUID()`; поля формы: `comment` (≤500), `pageUrl` (≤500), `width`, `height`; `@Throttle` 10/мин; `expiresAt = now + 72ч`.
  - `GET /:id/file` — `StreamableFile` inline (просмотр). Доступ: автор или SUPER_ADMIN.
  - `GET /:id/download` — то же + `Content-Disposition: attachment` (RFC 5987 для русского имени не нужно — имена ASCII).
  - `DELETE /:id` — автор или SUPER_ADMIN: строка БД + `fs.promises.unlink` файла.
- **service** — Prisma + fs; свипер по образцу `work-days.service.ts` (`OnModuleInit` + `setInterval`): каждые 30 мин (переопределяется env `SCREENSHOTS_CLEANUP_INTERVAL_MS`) удалять записи с `expiresAt <= now` вместе с файлами с диска.
- **dto** — class-validator для query/полей формы.
- Спека `screenshots.service.spec.ts` (jest): фильтр «свои/все», права на удаление, свипер удаляет просроченные + файл.

### 3. Статика и RBAC
- `backend/src/main.ts` — блокировать `/uploads/screenshots` ответом 403 (как `/uploads/recruitment`): файлы только через авторизованные эндпоинты.
- `backend/src/admin/admin-access/resources.config.ts` — `{ id: 'admin.screenshots', label: 'Скриншоты', path: '/admin/screenshots' }`.
- `backend/src/common/config/admin-api-route-resources.config.ts` — префикс `/api/v1/admin/screenshots` → `admin.screenshots` (GET → VIEW, мутации → EDIT).
- `backend/src/admin/admin-access/role-default-resources.config.ts` — добавить `'admin.screenshots'` во все роли (ADMIN, CONTENT_MANAGER, MODERATOR, SUPPORT, MANAGER, TECHNOLOGIST, PARTNER, BRIGADIER, обе LEAD_SPECIALIST_*, SURVEYOR, DRIVER, INSTALLER, TRAINEE) — дефолт даёт EDIT, т.е. доступен каждому админу.
- В `ADMIN_RESOURCE_PARENT` не добавлять — топовый раздел без родителя.

## Frontend (Next.js, FSD)

### 4. API-клиент `frontend/src/shared/api/admin-screenshots.ts`
Типы + `listAdminScreenshots`, `uploadAdminScreenshot` (FormData), `fetchAdminScreenshotBlob(id)` (GET `/file` → blob → objectURL для `<img>`), `downloadAdminScreenshot` (blob → `a[download]`), `deleteAdminScreenshot`. Авторизация — через `apiFetch` (сам прикрепляет Bearer).

### 5. Захват: `frontend/src/features/admin/screenshots/`
- `useScreenshotCapture.ts` — `getDisplayMedia({ video: { frameRate: 1 }, audio: false, preferCurrentTab: true, selfBrowserSurface: 'include' })` → скрытый `<video>` → `drawImage` на canvas → `canvas.toBlob('image/png')` → сразу `stop()` треков; отмена пользователя (AbortError) — без ошибки; отсутствие API — понятное сообщение «Работает на компьютере в Chrome/Edge/Firefox».
- `ScreenshotCaptureModal.tsx` — предпросмотр снимка, поле «Комментарий» (что случилось), кнопки «Сохранить» / «Снять заново» / «Отмена»; при сохранении отправляет файл + `pageUrl: window.location.pathname`; после успеха — плашка «Скриншот сохранён» со ссылкой на раздел.
- `AdminHeader.tsx` — кнопка-камера (`CameraIcon` из `@heroicons/react/24/outline`, стиль `styles.iconButton` рядом с переключателем темы) для всех админов.

### 6. Раздел админки
- `frontend/src/app/admin/screenshots/page.tsx` → `views/admin/Screenshots/` (`ScreenshotsPage.tsx`, `ScreenshotsPageView.tsx`, `ScreenshotsPage.module.css`, `index.ts`) — по образцу RemoteHelp/Users.
- Тулбар: счётчик, для SUPER_ADMIN — фильтры «Все / Мои» + селект автора, кнопка обновления (`AdminToolbarIconButton`).
- Сетка карточек: превью (blob-URL, клик — модалка полного вида), автор (для SA), дата, комментарий, ссылка `pageUrl`, бейдж «удалится через ~N ч» (`expiresAt`), кнопки: скачать, удалить (`ConfirmModal`).
- Сайдбар `AdminSidebar.tsx` `baseNavItems`: топ-пункт `{ label: 'Скриншоты', href: '/admin/screenshots', icon: '📷', resourceId: 'admin.screenshots' }` после «Онлайн-собраний».
- `frontend/src/shared/config/admin-resources.ts` — та же запись ресурса (зеркало бэка; `AdminSectionAccessShell` сам ограничит доступ по пути).

## Проверка
1. `cd backend && npx prisma migrate dev --name admin_screenshots` → `npm run build`, `npm run test` (новая спека).
2. `cd frontend && npm run lint && npm run build` (+ `node scripts/check-architecture.mjs` входит в сборку).
3. E2E вручную: поднять docker-compose (postgres + backend :3001 + frontend :3000), создать суперадмина (`npm run create-super-admin`); в браузере: кнопка 📷 → выбрать вкладку → сохранить → скрин появился в разделе; скачать, удалить; под обычным админом видны только свои скрины, у суперадмина — все.
4. TTL: создать запись с `expiresAt` в прошлом (psql) при `SCREENSHOTS_CLEANUP_INTERVAL_MS=5000` → убедиться, что запись и файл удалились автоматически.
