# Авторизация через Сбер ID

Интеграцию строим как зеркало существующего флоу Яндекс ID (authorization code + state-cookie), без новых зависимостей — обмен токенами через `fetch`, как в `yandex-auth.service.ts`.

## 1. Prisma
- `backend/prisma/schema.prisma`, модель `User`: добавить `sberId String? @unique` (по образцу `yandexId`, строка 45).
- Создать миграцию (`npx prisma migrate dev --name add_sber_id`) + `prisma generate`.

## 2. Backend: `backend/src/auth/sber-auth.service.ts` (новый, по образцу Яндекс-сервиса)
- Эндпоинты Сбера (прод, сверить с актуальной документацией при получении ключей):
  - authorize: `https://online.sberbank.ru/wa/oa/sberbank_id/authorize`
  - token: `https://online.sberbank.ru/wa/oauth/token`
  - userinfo: `https://online.sberbank.ru/sa/sberbank_id/profile`
- `getAuthorizationUrl(res)`: URL с `response_type=code`, `client_id`, `redirect_uri = ${SITE_URL}/auth/sber/callback`, `scope=openid name phone email`, `state` (random, httpOnly cookie `sber_oauth_state`, path `/api/v1/auth`, 10 мин — те же опции, что у Яндекса). Если ключи не заданы — `BadRequestException('Сбер ID не настроен (SBER_CLIENT_ID)')`.
- `exchangeCodeForUser(code, req, res)`:
  1. Проверка `state` через `timingSafeEqual` + очистка cookie (копия `assertStateCookie`).
  2. POST на token-endpoint (`application/x-www-form-urlencoded`, `grant_type=authorization_code`, `client_id`, `client_secret`, `code`, `redirect_uri`).
  3. GET userinfo c `Authorization: Bearer <access_token>`; из ответа берём `sub` (sberId), `email`, `phone`, `given_name`, `family_name`.
  2. Upsert пользователя по схеме «как у Яндекса»: поиск по `sberId` ИЛИ email (insensitive) ИЛИ phone; гостя — апгрейд (random-пароль `sber_...`, `isGuest=false`, привязка `sberId`); существующему без `sberId` — привязка; иначе создание нового через `usersService.create`. Если нет ни email, ни телефона — ошибка с понятным сообщением (email у Сбера опционален, в отличие от Яндекса, поэтому телефон используем как запасной идентификатор).
  3. Финал — `authService.login(...)` (выдача JWT + refresh-cookie), тот же формат возврата, что у Яндекса.
- Env: `SBER_CLIENT_ID`, `SBER_CLIENT_SECRET` (+ при необходимости `SBER_AUTH_URL`/`SBER_TOKEN_URL`/`SBER_USERINFO_URL` для тестового контура Сбера — вынести в `.env.example` с(prod-)дефолтами в коде). Задокументировать в корневом `.env.example` рядом с YANDEX_*.

## 3. Backend: `auth.controller.ts`
- `GET /auth/sber` → `{ url }` (аналог `GET /auth/yandex`).
- `POST /auth/sber/callback` с body `{ code, state }` (аналог яндексовского).
- `SberAuthService` добавить в провайдеры `AuthModule`.

## 4. Frontend
- `frontend/src/views/site/auth/LoginPageView.tsx`: кнопка «Войти через Сбер ID» рядом с яндексовской; `handleSberLogin` — fetch `GET /auth/sber`, валидация хоста (`online.sberbank.ru`), `window.location.href = url`.
- Новая страница-колбэк: `frontend/src/app/(site)/auth/sber/callback/page.tsx` + `SberCallbackPageView.tsx` (клон `YandexCallbackPageView.tsx`: парсинг `code`/`state` из query, POST `/auth/sber/callback`, сохранение сессии через существующие хелперы `auth-session.ts`, редирект как у Яндекса).
- Иконка/лого Сбера — простой стилизованный вариант без внешних ассетов.

## 5. Проверка
- `npx tsc --noEmit` / сборка бэкенда, сборка фронтенда, запуск существующих тестов.
- Флоу end-to-end проверить нельзя (ключей пока нет) — фича «включится» после заполнения `SBER_CLIENT_ID/SECRET` в `.env`; это же описать в плане/README.

Примечание: точные URL эндпоинтов и параметры (в т.ч. требуется ли Сбером PKCE) стоит сверить с официальной документацией Сбер ID при регистрации приложения — код структурирован так, что URL переопределяются через env без правок кода.
