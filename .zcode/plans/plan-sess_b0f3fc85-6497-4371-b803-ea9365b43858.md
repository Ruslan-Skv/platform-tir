# Позиция «Углы» в заказ-нарядах по Потолкам

## Контекст

В заказ-нарядах по Потолкам позиции берутся из «Счёт-заказа» (`form.estimate.snapshot`) и вообще не читают Спецификацию. «Углы» в Спецификации — это обычная строка в блоке «Доп. (фотопечать, углы, вырезы…)»: `form.ceilingsSpecification.ceilings[].extras[]` (тип `CeilingsNamedQtyLine`, имя из прайса, кол-во вводится вручную).

Цель: в **обоих** заказ-нарядах (вкладка «Заказ-наряд» — шаблон/печать/PDF/отправка клиенту, и «Итоговый заказ-наряд» в хабе) появляется позиция «Углы»: **кол-во — сумма из Спецификации**, **цена за штуку — новая глобальная настройка суперадмина** на странице «Наценки» (/admin/contract-documents/settings/markups). Цена из настроек — окончательная цена в заказ-наряде (наценка % и скидка по договору к ней НЕ применяются). Если цена не задана (пусто) — строка не добавляется. В заказ-нарядах по Д/с (workOrderAddendum1..5) строка не добавляется (углы — уровень договора).

## 1. Бэкенд: хранение цены угла

- **`backend/prisma/schema.prisma`** — модель `ContractDocumentRepairSettings` + колонка:
  `/// Стоимость одного угла в заказ-наряде потолков, ₽; null — не задана, строка «Углы» не добавляется.`
  `ceilingsWorkOrderCornerPrice Int?`
- **Новая миграция** `backend/prisma/migrations/20261109XXXXXX_ceilings_work_order_corner_price/migration.sql`:
  `ALTER TABLE "contract_document_repair_settings" ADD COLUMN "ceilingsWorkOrderCornerPrice" INTEGER;` (camelCase — по конвенции, см. миграцию 20260918160000).
- **`dto/settings/set-work-order-markup-by-kind.dto.ts`** — опциональное поле `ceilingsWorkOrderCornerPrice?: number | null` (`@IsOptional() @Type(() => Number) @IsInt() @Min(0)`; null/undefined — сброс/не менять).
- **`contract-document-package-kind-settings.service.ts`**:
  - `getWorkOrderMarkupSettings(kind)` — в ответ добавляется `ceilingsWorkOrderCornerPrice` (для CEILINGS — из БД, для остальных null);
  - `setWorkOrderMarkupSettings` — сохраняет поле, когда передано; не-CEILINGS с этим полем → `BadRequestException`;
  - `getWorkPeriodSettings` — для CEILINGS тоже возвращает `ceilingsWorkOrderCornerPrice` (редактор договора берёт настройки одним запросом).
- **`contract-document-packages.controller.ts`** (PUT work-order-markup-settings, ~L784) — пробросить поле в сервис.

## 2. Страница «Наценки»: поле «Углы, ₽» для «Натяжные потолки»

- **`frontend/src/shared/api/admin-contract-document-packages.ts`** — типы `WindowsWorkOrderMarkupSettings` (GET/PUT) и `WorkPeriodSettingsByKind` + поле `ceilingsWorkOrderCornerPrice?: number | null`.
- **`markupSettingsConstants.ts`** — в `MarkupKindSettingsSnapshot` добавить `cornerPrice: number | null`; конфиг CEILINGS получает `cornerPriceInputId`, load/save пробрасывают поле (остальные направления — null).
- **`hooks/useMarkupSettingsPage.ts`** — `MarkupRow` + `cornerPriceInput: string | null` и `savedCornerPrice: number | null`; сеттер `setCornerPriceInput`; парсинг (пусто → null, иначе целое ≥ 0 — новый `parseCornerPriceInput` в `markupSettingsUtils.ts`); учесть в dirty-проверке, валидации и сообщении «Сохранено».
- **`MarkupSettingsPageView.tsx`** — колонка «Углы, ₽» (редактируемая только в строке «Натяжные потолки», у остальных «—»), строка в мобильной карточке, обновить справку (helpText/sectionHint).

## 3. Кол-во углов из Спецификации

- **`ceilingsSpecification.ts`** — новый хелпер `sumCeilingsCornersQty(spec): number`: сумма `parseCeilingsQty(qty)` по всем `ceilings[].extras`, где `name.trim().toLowerCase() === 'углы'` (учитывает и ручные строки). Юнит-тесты в `ceilingsSpecification.test.ts`.

## 4. Строка «Углы» в шаблонном «Заказ-наряде»

- **`workOrderHtml.ts`** — новый хелпер `appendCeilingsCornersWorkOrderRoom(computed, cornerQty, cornerPrice)`: добавляет в `computed.rooms` синтетическую комнату `{ name: 'Доп. работы', lines: [{ name: 'Углы', unit: 'шт', quantity, originalPrice: price, originalAmount, adjustedPrice: price, adjustedAmount: qty×price }] }`, увеличивает `originalTotal`/`adjustedTotal` на сумму (`reductionAmount` не меняется — прибавляем поровну). Тест рядом с `workOrderHtml.discount.test.ts`.
- **`packageFormForTemplate.ts`** — в options добавить `ceilingsWorkOrderCornerPrice?: number | null`; после `resolveWorkOrderComputedForTemplate(form.estimate.snapshot, …)` (L379) применить хелпер, если `packageKind === 'CEILINGS'`, кол-во > 0 и цена != null. Тем самым накрывает предпросмотр, печать и отправку клиенту.
- Проброс опции по цепочке (повсюду по образцу `windowsWorkOrderMarkupPercent`):
  - `usePackageDocumentEditorController.ts` — новое состояние `ceilingsWorkOrderCornerPrice: number | null` (+ setter);
  - `usePackageDocumentLoad.ts` — заполнение состояния из ответа настроек (~L259-266);
  - `buildPackageTemplatePreviewHtml.ts`, `usePackageRenderedDocument.ts`;
  - `buildWorkOrderPdfForInstallationSchedule.ts` — при `packageKind === 'CEILINGS'` дозагрузить `getContractDocumentWorkOrderMarkupSettings('CEILINGS')` и передать цену (сейчас файл читает только WINDOWS-настройки);
  - `packageCustomerDocumentShare.ts` — для CEILINGS читать настройки наценок CEILINGS (сейчас ~L525 берёт WINDOWS) и передать цену в `buildPackageTemplatePreviewHtml`.

## 5. Строка «Углы» в «Итоговом заказ-наряде»

- **`usePackageFinalEstimateWorkOrders.ts`** — в options добавить `ceilingsWorkOrderCornerPrice: number | null`; в `finalWorkOrderComputed` для CEILINGS при qty>0 и цене != null: добавить синтетическую комнату (line `{key: 'ceilings-corners', name: 'Углы', unit: 'шт', quantity, price, amount, adjustedPrice: price, adjustedAmount}`) и увеличить `total`; в `finalWorkOrderCategorySections` добавить секцию `{categoryName: 'Доп. работы', …}` (иначе панель её не отрисует). НЕ включать в per-installer документы и «Итоги по мастерам» — углы не привязаны к мастеру.
- Проброс: `usePackageWorkOrderHubContext.ts` (+ тип `PackageWorkOrderHubContext.tsx` при необходимости) из состояния контроллера.

1. Миграция/схема: `cd backend && npx prisma generate && npx prisma migrate dev --create-only` (применение — на деплое).
2. Тесты: `cd frontend && npx jest src/views/admin/ContractDocuments/packages/families/product-like/ceilings/ceilingsSpecification.test.ts src/views/admin/ContractDocuments/packages/platform/form/workOrderHtml.discount.test.ts` + `npm run type-check && npm run lint`; бэкенд — `npm run build`.
3. Ручная проверка (по договору cmv6fw9y101smrurneokcm2xp):
   - «Наценки»: у «Натяжные потолки» появляется поле «Углы, ₽»; задать (например 350), сохранить — только суперадмин;
   - договор → Спецификация → блок «Доп. …» со строкой «Углы» и кол-вом → хаб «Заказ-наряды» → «Заказ-наряд»: внизу таблицы «Доп. работы» / строка «Углы» с кол-вом из спецификации и ценой из настроек, итог вырос;
   - «Итоговый заказ-наряд»: секция «Доп. работы» с «Углы», «Итого по итоговому заказ-наряду» вырос;
   - очистить цену в настройках → строка исчезает из обоих документов; кол-во углов суммируется по нескольким потолкам в спецификации.
