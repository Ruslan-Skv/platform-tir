# Кнопка «Настройки договоров» в шапке пакета: порог Акта начала работ + перенос 5 разделов

## Контекст

Кнопка «Зафиксировать „В работе“» (прикрепление Акта начала работ) уже показывается на предстоящих шагах (прошлый фикс), но её порог активности зашит константой 70%: фронт `packagePipeline.ts:29`, бэк `package-list-pipeline-status.ts:12`. Нужна:

1. Кнопка **«Настройки договоров»** в шапке редактора пакета (иконка `KnowledgePlatformSettingsIcon` — как у «Настройки дашборда»), **только SUPER_ADMIN**.
2. В модалке — настройка порога (по решению: действует **только на «Ремонт»**; продуктовые направления остаются на 70%).
3. В эту же модалку **перенести 5 разделов** (по решению: старые страницы/пункты навигации убираем полностью, URL → редирект): Исполнители (requisites), Менеджеры (signatories), Сроки договоров (settings), Нумерация (settings/numbering), Наценки (settings/markups).

## Бэкенд

1. **Prisma**: `ContractDocumentRepairSettings` (schema.prisma ~4396) + поле `repairWorkStartMinPayPercent Int?` (null → 70). Миграция `20261110120000_repair_work_start_min_pay_percent/migration.sql` по конвенции последних (camelCase, без default): `ALTER TABLE "contract_document_repair_settings" ADD COLUMN "repairWorkStartMinPayPercent" INTEGER;` + комментарий. Затем `npx prisma generate`.

2. **Сервис** `contract-document-package-kind-settings.service.ts`:
   - Экспортируемый хелпер `resolveRepairWorkStartMinPayPct(prisma): Promise<number>` (чтение REPAIR-строки, try/catch, clamp 1..100, default 70) — его же используют методы сервиса и внешние модули без DI-переплетений.
   - `getRepairSettings()` возвращает `workStartMinPayPercent` (числом).
   - Частичное обновление: в `SetRepairContractSettingsDto` `defaultWorkPeriodDays` сделать `@IsOptional()`, добавить `workStartMinPayPercent?` (`@IsOptional @IsInt @Min(1) @Max(100)`); `setWorkPeriodSettings` при upsert обновляет только переданные поля (иначе сохраняет текущие).

3. **Статусы списка** `list-pipeline/package-list-pipeline-status.ts`: опциональный вход `workStartMinPayPct?: number` у `explainPackageListPipelineStatus` / `computePackageListPipelineStatus`. В `workStartPaymentReady` (стр. ~626) для ремонтной семантики — `input.workStartMinPayPct ?? 70`, для продуктовых направлений — константа 70 (не трогаем `inferWindowsPrepayment70StartDate`).

4. **Протянуть настройку в 4 места вызова** (у всех есть prisma; резолвить один раз на запрос):
   - `contract-document-package-list.service.ts` (~156 — фильтры/счётчики очередей);
   - `contract-document-package-diagnostic-export.service.ts` (~138 и ~182);
   - `odpzh-schedules.service.ts` — параметр у чистой `buildOdpzhScheduleRow`, резолв в `findAll`;
   - `repair-schedules/repair-schedule-from-package.service.ts` (~207).

5. **Тесты**: расширить `package-list-pipeline-status.spec.ts` кейсами с нестандартным порогом.
