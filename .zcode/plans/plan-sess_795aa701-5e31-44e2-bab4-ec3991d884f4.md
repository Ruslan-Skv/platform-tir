# Новый раздел «Поставщики» (реквизиты + учёт оплат)

## Суть из Excel-файла (переносимая бизнес-логика)
- Вкладка «Итого»: список поставщиков с «Суммой к оплате» (сальдо конечное) и общим итогом.
- Вкладка поставщика: блок реквизитов (банк, р/с, БИК, ИНН, наименование) + ведомость: `Дата | № счёта | Сумма | Оплата | Примечание (№ договора) | НДС`, сальдо начальное, обороты, **сальдо конечное = сальдо начальное + Σ счетов − Σ оплат**.
- Особенности из файла: у одного «поставщика» бывает несколько юрлиц/реквизитов (Максидорс — 3, Вудэко — 2, ТД Века — 2) → несколько блоков реквизитов у одного поставщика; отрицательное сальдо = переплата; до 50–70 поставщиков.

## Решения (по ответам пользователя)
- Доступ как у «Кассы»/«ДП»: SUPER_ADMIN, ADMIN, MODERATOR, SUPPORT, TECHNOLOGIST, MANAGER, LEAD_SPECIALIST_FURNITURE, LEAD_SPECIALIST_WINDOWS_DOORS (роль — широкий фильтр, точный доступ через ресурс `admin.suppliers` в «Доступах»).
- Из Excel переносятся только текущие сальдо (поле «Сальдо начальное» у поставщика).
- Старые `/admin/crm/supplier-settlements` и `/admin/catalog/suppliers` (список+редактирование) удаляются; таблица `suppliers` остаётся той же — данные реквизитов никуда физически не двигаются; прайс-листы остаются на старом URL `/admin/catalog/suppliers/[id]/price-lists` со ссылкой из карточки.

## 1. Модель данных (Prisma, `backend/prisma/schema.prisma` + миграция)
- `Supplier`: + `openingBalance Decimal? @db.Decimal(14,2)`, + `openingBalanceDate DateTime?`.
- Новая `SupplierRequisite` (`supplier_requisites`): supplierId, name («ИП Ермаков», «Реквизиты до 2021»…), bankName, bankAccount, bankBik, corrAccount, inn, kpp, note, isDefault, sortOrder.
- Новая `SupplierLedgerEntry` (`supplier_ledger_entries`): supplierId, requisiteId?, date (DateTime), documentNo («№ 71 от 14 октября 2026 г.» — свободная строка), amount (начисление), payment (оплата), note (№ договора), vatRate Decimal? (null/0/20/22), createdById?, createdAt/updatedAt; индекс `[supplierId, date]`.
- Миграция `20261019..._suppliers_ledger_requisites`: создаёт таблицы/колонки; **переносит** плоские банковские поля suppliers → по одной записи `supplier_requisites` (если заполнены); копирует строки `supplier_settlement_rows` → `supplier_ledger_entries` (на случай, если данные всё же есть); дропает `supplier_settlement_rows`/`supplier_settlement_history`; удаляет пермиссии ресурса `admin.crm.supplier-settlements`.
- Скрипт `scripts/suppliers-opening-balances.sql` — текущие сальдо из Excel (Тугушев 4 800; ФИС 83 061,40; Ничепорович −532 512,40; Вудэко −745,83; Стройком 84 742; остальные 0) с сопоставлением по ИНН/названию — выполнить на проде после деплоя (или внести руками через UI).

## 2. Backend — новый модуль `backend/src/admin/suppliers/`

Эндпоинты (конверт `{ data, total, page, limit, totalPages, … }` как в кассе; баланс считается SQL-агрегатом groupBy):
- `GET /admin/suppliers/summary?search&status(ALL|PAYABLE|SETTLED|OVERPAY)&page&limit` — строки: поставщик, ИНН, контакты, число реквизитов, сальдо нач., начислено, оплачено, **к оплате**, дата последней записи + `totals: { payable, overpay, suppliersWithDebt, suppliersTotal }`.
- `GET /admin/suppliers/:id` — поставщик + реквизиты + стats + productsCount; `POST`/`PATCH`/`DELETE /admin/suppliers/:id` (DELETE с Conflict, если привязаны товары — как сейчас).
- `GET /admin/suppliers/:id/ledger?page&limit&search` (+amountSum/paymentSum/balance); `POST /admin/suppliers/:id/ledger`; `PATCH`/`DELETE /admin/suppliers/ledger/:entryId`.
- `POST /admin/suppliers/:id/requisites`; `PATCH`/`DELETE /admin/suppliers/requisites/:rid`.

Доступ: `admin-api-route-resources.config.ts` — префикс `/api/v1/admin/suppliers` → `admin.suppliers` (GET=VIEW, мутации=EDIT через AdminResourceInterceptor).
